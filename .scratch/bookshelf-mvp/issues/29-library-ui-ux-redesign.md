# 29 — Переработка UI/UX личной библиотеки

**What to build:** Переработать текущий экран личной библиотеки так, чтобы он выглядел как целостное desktop-приложение и ясно направлял самостоятельного читателя к следующему полезному действию. Визуальная система должна поддерживать предметный образ Bookshelf, а интерфейс — показывать только понятные пользователю возможности и состояния, не выставляя технические проверки рабочего состояния как основную функцию продукта.

**Blocked by:** 28 — UI-фундамент на Bits UI и Tailwind CSS.

**Status:** ready-for-human

- [x] До реализации зафиксирован краткий UX-аудит текущего экрана: проблемы иерархии, навигации, понятности действий, обратной связи и адаптивности.
- [x] Для пустой и заполненной библиотеки определены отдельные пользовательские сценарии, основной следующий шаг и ожидаемая обратная связь.
- [x] Компоновка, типографика, цвета, интервалы и плотность информации образуют цельную визуальную систему Bookshelf без ощущения шаблонного web-dashboard.
- [x] Пустое состояние объясняет пользу библиотеки и предлагает доступное действие; будущие или недоступные функции не выглядят активными и не создают ложных ожиданий.
- [x] Техническая «пометка пространства» сохраняет проверяемое поведение, но не конкурирует с библиотекой за главное внимание и получает понятное пользователю назначение либо переносится в подходящий вторичный экран.
- [x] Навигация ясно различает текущий раздел, доступные переходы и ещё не реализованные возможности; неинтерактивные элементы не маскируются под рабочие controls.
- [x] Состояния загрузки, пустого результата, сохранения, успеха, ошибки и disabled оформлены последовательно, не вызывают скачков компоновки и сообщаются assistive technologies.
- [x] Все интерактивные элементы доступны с клавиатуры, имеют видимый focus state, достаточную область нажатия и корректные accessible name/role/state.
- [x] Экран остаётся пригодным для использования при ширине окна от 720 px и корректно перестраивается на меньшей ширине без горизонтальной прокрутки основного содержимого.
- [ ] Поведение пустой библиотеки и сохранения локальной пометки покрыто пользовательскими frontend-тестами; визуальный результат проверен на собранном Tauri-приложении и зафиксирован скриншотами до/после.

## Comments

UX-аудит и сценарии сохранены в `ux-audit.md`; пользовательские тесты покрывают пустое состояние и сохранение, а Windows release smoke автоматически публикует текущий desktop-скриншот. Историческое «до» честно зафиксировано аудитом, так как исполняемый старый кандидат отсутствует.
