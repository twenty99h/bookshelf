# Bookshelf MVP

Status: complete

## Problem Statement

Самостоятельный читатель технической книги часто завершает чтение с набором выделений и ощущением знакомости с материалом, но без подтверждённой способности применить идеи в работе, восстановить их спустя время или содержательно передать другому человеку. Обычные PDF-просмотрщики и заметочники помогают сохранить текст, но не поддерживают целостное изучение книги: авторскую формулировку идей, явную работу с долгом изучения, практические эксперименты, восстановление знания и ретроспективу книги.

Самостоятельному читателю нужен локальный desktop-инструмент, который поддерживает этот цикл без обязательного наставника, учебной группы, облачного аккаунта или постоянного доступа к ИИ. Инструмент должен сохранять происхождение каждой идеи, не подменять авторскую работу генерацией ИИ, не блокировать чтение из-за накопившегося долга и оставлять читателю окончательный выбор следующего действия.

## Solution

Создать Bookshelf — локальное однопользовательское desktop-приложение для системного изучения технических PDF-книг. Приложение объединяет личную библиотеку, встроенное чтение, черновые заметки, идеи книги, темы знаний, практические эксперименты, восстановление знания, материалы для передачи и ретроспективу книги в одном управляемом процессе.

Bookshelf владеет рабочим состоянием изучения и рекомендует следующий шаг, но не строит обязательный автоматический маршрут. Основной цикл работает без сети и без ИИ. По явному запросу читателя приложение передаёт локальному Codex App Server минимальный пакет проверки, чтобы получить критику уже сформулированной идеи; полный PDF, личная библиотека и не относящийся к запросу контекст не передаются. Готовые материалы односторонне экспортируются в Markdown, а личная библиотека переносится между компьютерами цельным зашифрованным архивом.

Первая поставка ориентирована на Windows, при этом приложение строится на Tauri 2 с Rust backend и Svelte frontend, чтобы сохранить возможность последующих сборок для macOS и Linux.

## User Stories

1. Как самостоятельный читатель, я хочу импортировать PDF в личную библиотеку, чтобы изучать принадлежащую мне локальную копию книги.
2. Как самостоятельный читатель, я хочу видеть понятное сообщение о PDF без текстового слоя, чтобы знать, почему выделение текста недоступно.
3. Как самостоятельный читатель, я хочу открыть импортированную книгу во встроенном просмотрщике, чтобы не переключаться между приложениями во время изучения.
4. Как самостоятельный читатель, я хочу продолжить чтение с сохранённой страницы, масштаба и позиции, чтобы быстро вернуться к прерванному сеансу изучения.
5. Как самостоятельный читатель, я хочу использовать встроенное оглавление PDF, чтобы переходить к нужным главам и разделам.
6. Как самостоятельный читатель, я хочу исправлять оглавление и создавать отсутствующие главы или разделы, чтобы источники идей соответствовали реальной структуре книги.
7. Как самостоятельный читатель, я хочу иметь только одно изучение книги в активной фазе, чтобы сохранять фокус.
8. Как самостоятельный читатель, я хочу продолжать эксперименты и восстановления из других книг, чтобы завершение активной фазы не обрывало полезную работу.
9. Как самостоятельный читатель, я хочу задавать недельный ритм изучения в сеансах, чтобы регулярно уделять книге время без искусственного дедлайна.
10. Как самостоятельный читатель, я хочу планировать сеанс изучения с конкретным намерением, чтобы оценивать работу по смыслу, а не по числу страниц.
11. Как самостоятельный читатель, я хочу явно перенести, заменить или отменить пропущенный сеанс с причиной, чтобы осознанно корректировать план без штрафов.
12. Как самостоятельный читатель, я хочу получать рекомендуемый следующий шаг, чтобы легче выбирать полезное продолжение изучения.
13. Как самостоятельный читатель, я хочу самостоятельно выбирать фактическое занятие сеанса, чтобы рекомендация не превращалась в обязательное задание.
14. Как самостоятельный читатель, я хочу всегда иметь возможность продолжить чтение, чтобы долг изучения не блокировал основной процесс.
15. Как самостоятельный читатель, я хочу выделить фрагмент книги и быстро сохранить черновую заметку с комментарием или без него, чтобы не разрушать поток чтения.
16. Как самостоятельный читатель, я хочу завершить сеанс с неразобранными черновыми заметками, чтобы разбор не был обязательным условием каждого чтения.
17. Как самостоятельный читатель, я хочу видеть очередь разбора между сеансами, чтобы временные записи не терялись.
18. Как самостоятельный читатель, я хочу удалить черновую заметку, присоединить её к существующей идее, превратить в новую идею или экспортировать во внешний архив, чтобы осознанно решить её судьбу.

## Implementation Decisions

- Bookshelf является локальным однопользовательским desktop-приложением. Рабочее состояние и импортированные PDF хранятся локально; отдельный аккаунт Bookshelf не требуется.
- Первая поддерживаемая поставка ориентирована на Windows. Реализация использует Tauri 2, Rust backend и Svelte 5/TypeScript frontend, сохраняя возможность последующих сборок для macOS и Linux.
- Rust владеет постоянным состоянием, доменными инвариантами и сценариями приложения. Frontend владеет представлением и незавершённым состоянием взаимодействия.
- Межпроцессный интерфейс состоит из небольших предметных команд и событий. Frontend не получает универсальный доступ к SQL, файловой системе или shell и не собирает атомарные предметные операции из цепочки низкоуровневых вызовов.
- Входные данные проверяются в Rust независимо от frontend-валидации. Публичные DTO имеют единое Rust-описание, из которого генерируются TypeScript bindings; несовпадение сохранённых bindings считается ошибкой проверки.
- Рабочее состояние хранится в SQLite. Полнотекстовый поиск реализуется через FTS5 внутри SQLite-адаптера и не входит в доменную модель.
- Изменения, затрагивающие несколько сущностей, выполняются транзакционно. Миграции применяются до открытия основного окна; восстановление после прерванной записи является обязательным сценарием проверки.
- PDF.js используется как собственный встроенный viewer, а не как неизменённый generic viewer. Модуль чтения скрывает загрузку из личной библиотеки, оглавление, выделение, источник, позицию и различия системных WebView.
- В MVP поддерживаются PDF с доступным текстовым слоем. OCR, EPUB, Kindle и другие форматы не входят в объём.
- Доступ WebView к внутренней библиотеке ограничен необходимым каталогом и политикой CSP. PDF.js, worker, шрифты и character maps поставляются локально без CDN.
- Только одно изучение книги находится в активной фазе. Завершение чтения и завершение изучения являются разными явными переходами; открытые эксперименты не блокируют завершение изучения.
- Продолжение чтения всегда доступно. Долг изучения показывается отдельно и влияет на рекомендацию, но не вытесняет чтение и не создаёт штрафов или серии дней.
- Идея книги требует авторской формулировки и источника на уровне книги и главы или раздела. Страница и фрагмент являются дополнительным контекстом, а не заменой самостоятельной идеи.
- Назначение идеи является множественным. Практический эксперимент не обязателен для каждой идеи.
- Тема знаний и связь идей создаются или подтверждаются читателем. ИИ не меняет тематическую структуру самостоятельно.
- Восстановление знания скрывает готовую формулировку до ответа и завершается самооценкой читателя. ИИ может указать пробелы, но не выставляет итоговую оценку.
- Практический эксперимент считается завершённым только при наличии ситуации, действия, наблюдаемого результата и вывода. Положительный исход не требуется.
- Материал для передачи создаётся читателем. Приложение предлагает структуру и ссылки на предметные записи, но не генерирует авторский текст автоматически.
- Bookshelf является источником истины для рабочего состояния. Экспорт в Markdown и возможная будущая интеграция с Google Calendar односторонние; двусторонняя синхронизация не предусматривается.
- Codex поставляется как версионированный Tauri sidecar и запускается Rust-адаптером только для входа или явного действия ИИ. Bookshelf общается с Codex App Server через стандартный потоковый JSONL transport.
- Codex запускается с отдельными каталогами состояния и изолированной рабочей папкой без доступа к личной библиотеке. Bookshelf не читает и не хранит OAuth-токены.
- Пакет проверки содержит только инструкцию, источник идеи, выбранный фрагмент, авторскую формулировку, конкретный вопрос и критерии ответа. PDF целиком, эксперименты и другие заметки автоматически не добавляются.
- При недоступности интеграции тот же пакет проверки можно вручную перенести во внешний чат. Ошибки входа, несовместимая схема, отсутствие sidecar, crash и отмена не повреждают состояние и не блокируют основной цикл.
- Полный ответ ИИ временный: после разбора постоянно сохраняются факт проверки, решение читателя, авторская формулировка и необязательный вывод.
- Личная библиотека имеет одну рабочую копию и переносится редко цельным архивом. Постоянная синхронизация и Git как рабочее хранилище исключены.
- Полный переносимый архив включает PDF и рабочее состояние и всегда шифруется пользовательским паролем без восстановления. Облегчённые автоматические снимки не включают книги.
- ChatGPT OAuth-токены, состояние входа и журналы Codex не включаются в переносимый архив; после переноса требуется новый вход.
- Точный криптографический формат архива остаётся предметом отдельного прототипа. Предпочтителен проверяемый потоковый формат на основе стандартной библиотеки; собственная криптографическая схема не разрабатывается.
- Установщик и обновления должны поставлять совместимую пару Bookshelf и Codex. Sidecar не обновляется независимо от приложения; обновления приложения принимаются только с проверяемой подписью.

## Testing Decisions

- Основной и самый высокий seam — собранное Tauri desktop-приложение. Сквозные тесты проверяют пользовательские результаты через видимый интерфейс и предметное поведение, не обращаясь напрямую к внутренним таблицам, компонентам или приватным функциям.
- Хороший тест описывает наблюдаемое поведение самостоятельного читателя: сохранённое состояние после перезапуска, доступность продолжения чтения, явное подтверждение действий ИИ, корректное восстановление архива или сохранность данных после отказа. Тесты не фиксируют внутреннее размещение модулей, структуру DOM без пользовательского смысла или конкретную последовательность приватных вызовов.
- Через desktop seam проверяются основные критерии MVP: импорт и продолжение чтения PDF; создание черновой заметки из выделения; разбор в идею с источником и назначением; явная проверка идеи; ручной fallback; локальный поиск; восстановление знания; завершение эксперимента; раздельное отображение чтения и долга; экспорт материала; ретроспектива; перенос зашифрованного архива и повторный вход после переноса.
- Rust application seam используется только для плотной матрицы доменных инвариантов и отказов, которые непрактично исчерпывающе воспроизводить через desktop UI: атомарный разбор черновика, допустимые переходы изучения, обязательные поля эксперимента, расчёт следующего восстановления и решения по пропущенному сеансу.
- SQLite-адаптер проверяется интеграционно на временной реальной базе. Тесты покрывают миграции, внешние ключи, полнотекстовый поиск, транзакции, облегчённые снимки и восстановление после прерванной записи.
- Svelte-сценарии тестируются через Testing Library с fake-адаптером предметных команд только там, где требуется быстро проверить доступность, клавиатурное управление, фокус, валидацию формы и визуальные состояния streaming/error/cancel. Эти тесты формулируются на языке пользовательского поведения.
- PDF vertical slice проверяется на корпусе технических PDF с колонками, листингами, формулами, разными встроенными шрифтами, ошибочным порядком текста, повреждённым оглавлением и большим размером. Ключевой результат — сохранение корректного источника выделения и восстановление позиции после перезапуска.
- Codex vertical slice проверяет запуск bundled sidecar, ChatGPT-вход, отправку ровно одного минимального пакета проверки, поток ответа, отмену, crash, несовместимость протокола и отсутствие доступа к личной библиотеке.
- Archive vertical slice проверяет большой архив, правильный и неправильный пароль, обрыв записи, повреждение, версионную несовместимость, дубликаты и восстановление поддерживаемым внешним инструментом выбранного формата.
- Packaging vertical slice проверяет чистую установку на Windows-машине без Rust и Node.js, наличие совместимого bundled Codex и отказ от неподписанного обновления.
- Существующим prior art является зафиксированная в архитектуре стратегия: Rust unit tests, интеграционные тесты SQLite, Vitest и Testing Library для Svelte, а также WebdriverIO с Tauri service для сквозных desktop-сценариев. При появлении кода новые тесты должны следовать ближайшему существующему сценарию того же уровня.
- Минимальная CI-матрица до кроссплатформенного релиза запускает проверки на Windows для каждого изменения; release candidate дополнительно проверяется на Windows, macOS и Linux, поскольку архитектура должна сохранять переносимость.

## Out of Scope

- OCR и выделение текста в сканированных PDF без текстового слоя.
- EPUB, Kindle и другие форматы книг.
- Мобильное приложение.
- Постоянная синхронизация между компьютерами.
- Совместная библиотека, несколько пользователей, наставники и учебные группы.
- OpenAI Platform API, отдельная оплата токенов и хранение API-ключей Bookshelf.
- Автоматическое извлечение идей, генерация конспекта или автоматическое изменение тем и связей.
- Семантический ИИ-поиск.
- Двусторонняя синхронизация с Obsidian.
- Интеграция с Google Calendar в MVP.
- Браузерное расширение для статей и документации.
- Встроенная социальная лента или публичная платформа материалов.
- Git как рабочее хранилище личной библиотеки.
- Отдельное шифрование рабочей локальной библиотеки поверх защиты диска операционной системы.
- Гарантированный первый релиз для macOS и Linux; эти платформы остаются последующим развитием после Windows-first поставки.

## Further Notes

- Результат изучения измеряется способностью применить и передать идеи, а не количеством страниц, выделений или завершённых глав.
- Наиболее рискованные предположения должны проверяться ограниченными вертикальными прототипами до расширения реализации: PDF.js в системных WebView, потоковый Codex App Server как bundled sidecar, восстановление SQLite после сбоя, чистая установка и криптографический формат переносимого архива.
- Codex App Server и его схема считаются экспериментальной зависимостью. Версия sidecar фиксируется вместе с Bookshelf, а протокольные изменения изолируются в адаптере.
- Текстовый слой технических PDF может неверно представлять колонки, формулы и листинги; поэтому реальный корпус PDF важнее искусственных простых документов.
- Уведомления о долге не должны становиться фоновым шумом. Они ненавязчивы, не появляются во время чтения и не превращаются в штрафы.
- Сложность формы идеи является продуктовым риском: обязательными остаются только самостоятельная формулировка и источник; дополнительные поля должны оправдываться дальнейшей работой.
- Решение Tauri является актуальным и заменяет ранее рассмотренное решение .NET/WinUI. Новая реализация не должна опираться на superseded стек.
