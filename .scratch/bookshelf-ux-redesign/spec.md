# UX-переработка Bookshelf

Status: ready-for-agent

## Problem Statement

Текущий прототип Bookshelf подтверждает отдельные функции системного изучения книг, но не поддерживает главный пользовательский поток как цельное desktop-приложение. Режим чтения занимает только часть рабочего стола, показывает одну страницу, конкурирует с глобальной навигацией и заставляет переходить к форме ниже PDF, когда читателю нужно быстро сохранить источник мысли. Библиотека, черновые заметки, идеи книги, восстановления знания, практические эксперименты и настройки собраны в одном state-only стеке без восстанавливаемых адресов и ясных рабочих контекстов.

Самостоятельному читателю нужен спокойный локальный инструмент, в котором продолжение чтения важнее незавершённой работы, источник сохраняется без потери контекста, а осмысление происходит отдельным намеренным действием. Интерфейс не должен превращать изучение книги в календарь, единый процент, streak или административный список задач. Команде разработки нужна последовательная спецификация целевого UX, контрактов и визуальной проверки, чтобы заменить прототип восемью самостоятельно проверяемыми вертикальными этапами без потери текущего предметного поведения.

## Solution

Перестроить Bookshelf вокруг адресуемых SvelteKit-контекстов: рабочего стола, библиотеки, страницы книги, отдельного режима чтения, очереди разбора, знаний, идеи, практики и настроек. Основной shell обслуживает навигацию и повседневные разделы, а reader получает защищённое внутреннее пространство без глобальной навигации. Приложение остаётся однооконным: адреса нужны для восстановления контекста, истории переходов и устойчивых E2E-сценариев, а не для параллельной работы.

Режим чтения станет непрерывным виртуализированным PDF-reader с постоянным toolbar, универсальным правым сайдбаром, поиском, оглавлением, цифровым полем источников и автосохранением позиции, масштаба и layout. Выделение по умолчанию сохраняется как черновая заметка; идея книги появляется только после самостоятельной формулировки. Остальные экраны поддерживают последовательный разбор, master-detail знаний, восстановления, практические эксперименты, сохраняемое завершение изучения и раздельные вехи прогресса без календарных сеансов.

Редизайн использует тёмную инструментальную систему Night/Graphite/Slate/Mist с Iris для действий и Amber только для происхождения знания, локальные IBM Plex Sans/Mono, Tailwind CSS и Bits UI через собственные shared-примитивы. Визуальный контракт защищается Playwright browser E2E с детерминированным adapter, Page Object Model, двенадцатью Full HD baseline-скриншотами и небольшим набором невидимых, keyboard-only и accessibility-инвариантов. Нативный Tauri suite остаётся узким smoke-контуром для импорта PDF и восстановления позиции.

## User Stories

1. Как самостоятельный читатель, я хочу при запуске сразу видеть активную книгу, чтобы продолжить чтение без разбора незавершённой работы.
2. Как самостоятельный читатель, я хочу видеть незавершённую работу отдельно от действия продолжения чтения, чтобы черновики, проверки и эксперименты не блокировали книгу.
3. Как самостоятельный читатель, я хочу видеть спокойный недельный итог содержательных вех, чтобы понимать, переходит ли текст в знание, не измеряя время в приложении.
4. Как новый самостоятельный читатель, я хочу увидеть одно понятное действие импорта PDF и объяснение локального хранения, чтобы начать без обучающей карусели и обязательной настройки.
5. Как самостоятельный читатель, я хочу переходить между рабочим столом, библиотекой, черновиками, знаниями, практикой и настройками через подписанные иконки, чтобы всегда понимать текущий контекст.
6. Как самостоятельный читатель, я хочу возвращаться к книге, идее или режиму чтения по устойчивому адресу, чтобы контекст восстанавливался после перезапуска.
7. Как самостоятельный читатель, я хочу использовать естественную историю переходов, чтобы кнопка «Назад» возвращала меня в ожидаемый рабочий контекст.
8. Как самостоятельный читатель, я хочу работать в одном окне, чтобы Bookshelf не создавал конкурирующие рабочие контексты.
9. Как самостоятельный читатель, я хочу видеть в библиотеке 8–10 книг при Full HD, чтобы быстро сравнивать статусы без декоративной сетки обложек.
10. Как самостоятельный читатель, я хочу видеть для каждой книги статус изучения, последнюю позицию, число черновых заметок и одно главное действие, чтобы выбрать следующий шаг без перегрузки.
11. Как самостоятельный читатель, я хочу фильтровать библиотеку по активным, приостановленным, готовым, завершённым и архивным книгам, чтобы находить нужный цикл изучения.
12. Как самостоятельный читатель, я хочу сортировать книги по последнему обращению, названию или прогрессу чтения, чтобы организовать список под текущую задачу.
13. Как самостоятельный читатель, я хочу после импорта увидеть название, число страниц, оглавление, наличие текстового слоя и ошибки открытия, чтобы оценить пригодность PDF без лишнего редактора метаданных.
14. Как самостоятельный читатель, я хочу при импорте дубликата перейти к существующей книге, чтобы не создавать две копии одного содержимого.
15. Как самостоятельный читатель, я хочу открывать страницу книги с обзором, черновиками, идеями и практикой, чтобы видеть весь процесс изучения в контексте источника.
16. Как самостоятельный читатель, я хочу архивировать книгу без удаления PDF, источников и истории, чтобы убрать её из основных представлений с возможностью вернуть.
17. Как самостоятельный читатель, я хочу постоянно удалить книгу только через вторичное действие с ясными последствиями, чтобы не потерять знания случайно.
18. Как самостоятельный читатель, я хочу справочно читать завершённую книгу с сохранением позиции, чтобы возвращаться к тексту без нового активного изучения.
19. Как самостоятельный читатель, я хочу явно начать повторное изучение завершённой книги, чтобы сохранить прежнюю ретроспективу и создать новый цикл.
20. Как самостоятельный читатель, я хочу, чтобы режим чтения занимал всё внутреннее пространство окна, чтобы PDF был главным визуальным объектом.
21. Как самостоятельный читатель, я хочу скрыть глобальную навигацию в режиме чтения, чтобы она не отвлекала от текста.
22. Как самостоятельный читатель, я хочу постоянно видеть возврат, книгу, позицию, поиск, масштаб, сохранение и переключатель сайдбара, чтобы основные действия не исчезали при прокрутке.
23. Как самостоятельный читатель, я хочу прокручивать PDF непрерывной лентой, чтобы переход между страницами не прерывал чтение.
24. Как самостоятельный читатель, я хочу, чтобы длинный PDF виртуализировался без блокировки toolbar и скачков геометрии, чтобы reader оставался отзывчивым.
25. Как самостоятельный читатель, я хочу открывать в одном правом сайдбаре заметку, оглавление или поиск, чтобы дополнительные инструменты не конкурировали друг с другом.
26. Как самостоятельный читатель, я хочу изменять ширину сайдбара и сохранять её для каждой книги, чтобы reader соответствовал конкретному материалу.
27. Как самостоятельный читатель с окном 1280×720, я хочу видеть сайдбар как drawer, чтобы документ сохранял рабочую ширину.
28. Как самостоятельный читатель, я хочу восстановить страницу, самую дальнюю страницу, масштаб, прокрутку, режим документа и layout после перезагрузки, чтобы продолжить с того же места.
29. Как самостоятельный читатель, я хочу выделить текст и одним действием открыть заполненную форму черновой заметки, чтобы не копировать источник вручную.
30. Как самостоятельный читатель, я хочу сохранить черновую заметку через `Ctrl+Enter` без модального окна, чтобы сразу вернуться к тексту.
31. Как самостоятельный читатель, я хочу видеть пять последних черновых заметок книги рядом с текущей формой, чтобы не создавать случайные повторы.
32. Как самостоятельный читатель, я хочу оформить выделение как идею отдельным действием, чтобы источник сохранился до самостоятельной формулировки.
33. Как самостоятельный читатель, я хочу сохранить один черновик с несколькими постраничными источниками, чтобы корректно захватывать мысль на границе страниц.
34. Как самостоятельный читатель, я хочу видеть сохранённые фрагменты янтарной подсветкой и маркерами цифрового поля, чтобы происхождение знания оставалось заметным.
35. Как самостоятельный читатель, я хочу переходить от маркера к черновой заметке и видеть связь с панелью при выборе или наведении, чтобы сопоставлять мысль и источник без визуального шума.
36. Как самостоятельный читатель, я хочу читать PDF без текстового слоя и создавать ручную заметку к странице, чтобы отсутствие выделения не блокировало работу.
37. Как самостоятельный читатель, я хочу переключать приглушённый светлый, оригинальный и тёмный режим PDF, чтобы читать комфортно при тёмном shell.
38. Как самостоятельный читатель, я хочу отдельно управлять инверсией изображений, чтобы технические схемы сохраняли смысл.
39. Как самостоятельный читатель, я хочу видеть компактные состояния «Сохранение…», «Сохранено» и «Не сохранено» с повтором, чтобы доверять автосохранению без постоянных toast.
40. Как самостоятельный читатель, я хочу разбирать одну черновую заметку вместе с книгой и источником, чтобы сосредоточиться на одном решении.

## Implementation Decisions

- Переработка поставляется восемью последовательными этапами: визуальная страховочная сетка; визуальный фундамент и shell; режим чтения; адресуемая библиотека; черновики и знания; практика и завершение; вехи и прогресс; данные и production hardening. Каждый этап обязан давать самостоятельно проверяемый пользовательский результат и оставлять репозиторий в рабочем состоянии.
- Информационная архитектура состоит из рабочего стола, библиотеки, страницы книги, режима чтения, черновиков, знаний, адресуемой идеи, практики и настроек. Архив остаётся фильтром библиотеки, темы — фильтрами знаний.
- Маршруты представляют восстанавливаемые рабочие контексты согласно ADR-0008. Приложение сохраняет одно desktop-окно и не поддерживает параллельные рабочие контексты.
- SvelteKit route entries остаются тонкими. Экранная композиция, page-local state, формы и одноразовые сценарии принадлежат соответствующим page slices; глобальный shell, маршрутизация, theme bootstrap, глобальные стили и локальные шрифты принадлежат app-уровню.
- Frontend сохраняет минимальный Feature-Sliced Design: app, pages и shared. Features и entities создаются только для фактически повторно используемых стабильных взаимодействий или моделей; widgets заранее не вводится. Срезы импортируются через публичные API, shared не содержит предметной логики.
- Основной shell содержит навигацию с Lucide-иконкой и текстом; настройки закреплены внизу. Reader использует отдельный shell без основной навигации.
- Page-local session продолжает владеть атомарным снимком состояния, типизированной навигацией и последовательным выполнением изменяющих предметных команд. Состояние незавершённой формы остаётся у формы; глобальный frontend-store не вводится.
- Production Tauri adapter и browser test adapter реализуют один интерфейс предметных команд. Test adapter детерминирован, исключается из production bundle, обслуживает тестовый PDF, записывает команды и моделирует loading/error/Codex-сценарии.
- Reader использует display layer PDF.js, непрерывную виртуализированную ленту, pre-render соседних страниц и placeholders стабильной геометрии. Дальние страницы освобождаются; отдельный ручной облегчённый режим не вводится.
- Постоянный reader toolbar содержит возврат, книгу и главу, позицию, масштаб, поиск, состояние сохранения и управление сайдбаром. F11 делегирует системный fullscreen стандартному desktop-окну.
- Универсальный правый сайдбар объединяет заметку, оглавление и поиск. На Full HD он сдвигает и центрирует документ, имеет начальную ширину около 400 px и диапазон 320–560 px; при меньшем рабочем viewport становится drawer. Открытая вкладка и ширина сохраняются для каждой книги.
- Состояние чтения включает последнюю и самую дальнюю страницу, масштаб, позицию прокрутки, режим документа, состояние и ширину сайдбара. Закрытие reader не требует подтверждения; сохранение отображается компактным состоянием в toolbar.
- Выделение сначала создаёт черновую заметку с явными постраничными источниками. Самостоятельная идея книги возникает только после отдельной авторской формулировки; автоматическое назначение восстановления удаляется.
- Один черновик может ссылаться на несколько соседних страниц. Каждый источник хранит собственную страницу и фрагмент; многостраничное выделение не схлопывается в неадресуемую цитату.
- PDF без текстового слоя поддерживает чтение и ручную заметку к странице. OCR, выделение изображений и рукописные аннотации не добавляются.
- Книга определяется по hash содержимого PDF. Дубликат ведёт к существующей книге; новая редакция импортируется как новая книга, замена файла существующей книги не поддерживается.
- Статусы изучения различают активное, приостановленное, готовое к завершению, завершённое, повторное и архивное состояния. Смена активной книги приостанавливает предыдущую; архивирование сохраняет PDF, источники и историю.
- Повторное изучение создаёт новый цикл и сохраняет прежнюю ретроспективу. Справочное чтение не становится параллельным активным изучением и не разрешает черновые заметки без явной активации книги.
- Разбор черновиков сфокусирован на одной записи. Создание идеи, присоединение источника, откладывание, экспорт и удаление являются явными решениями; полный список остаётся вторичным режимом.
- Знания используют master-detail примерно 38/62 при Full HD и drawer для детали при меньшем viewport. Идея принадлежит одной книге, допускает несколько источников этой книги и связывается с идеями других книг без слияния.
- Проверка Codex запускается только явным действием на идее. Источник, авторская формулировка и feedback видны одновременно; ответ не изменяет идею автоматически. Ошибка и ручной fallback локальны для секции проверки.
- Практика объединяет восстановления и эксперименты независимо от статуса книги. Восстановление скрывает исходную формулировку до ответа и заканчивается самооценкой читателя; предложенный следующий момент можно изменить.
- Эксперимент имеет закрытые состояния «Замысел», «Выполняется», «Подведение итогов», «Завершён» и «Отменён с причиной». Отрицательный результат считается завершённым практическим применением; обязательные дедлайны отсутствуют.
- Завершение изучения является сохраняемым пошаговым сценарием: завершение чтения, выбор 3–7 идей, ретроспектива книги, решение по незавершённой работе, перечисление продолжающихся экспериментов и подтверждение.
- Формальные StudySession, недельный бюджет, пропуски, календарное расписание и «долг изучения» удаляются из модели и UI согласно ADR-0007. История строится из датированных вех изучения, а накопившиеся действия называются «незавершённой работой».
- Прогресс чтения вычисляется по самой дальней позиции и не уменьшается при возврате назад. Прогресс изучения показывает раздельные результаты чтения, разбора, восстановления и практического применения без единого процента, таймера или streak.
- Глобальная командная панель ищет книги, идеи, темы, черновики и материалы и ведёт непосредственно в адресуемый контекст. Поиск reader работает только по текстовому слою текущего PDF и не сохраняет данные сам.
- Визуальная система тёмная и инструментальная: Night — фон, Graphite — рабочая поверхность, Slate — поднятые панели и controls, Mist — текст, Iris — действие/активный контекст/focus, Amber — только источник, выделение и маркеры. Success и danger остаются семантическими токенами.
- IBM Plex Sans используется для интерфейса и пояснений, IBM Plex Mono — только для страниц, дат, состояний и чисел. Шрифты поставляются локально как глобальный app-ресурс.
- Tailwind CSS оформляет прикладной UI. Глобальный CSS ограничен tokens, reset, fonts и reduced-motion baseline; отдельное исключение допускается для vendor/display-layer правил PDF.js text layer без прикладных селекторов Bookshelf.
- Bits UI используется только за собственными shared UI wrappers. Перед созданием или изменением конкретного Bits-примитива реализация обязана свериться с актуальным `llms.txt` этого компонента. Нативные input/textarea остаются внутри типизированных wrappers.
- Визуальная иерархия строится тремя уровнями тона, пространством и типографикой. Тени минимальны, скругления умеренны; стекло, glow и градиенты отсутствуют. Функциональная анимация длится 160–200 мс и отключается при reduced motion.
- Единственный намеренный фирменный риск — цифровое поле книги с маркерами источников. Iris и Amber имеют разные роли, чтобы действие и происхождение знания различались без чтения текста.
- Ошибки располагаются на минимальном затронутом уровне: поле рядом с полем, панель внутри панели с повтором, невозможность открыть личную библиотеку — на отдельном восстановительном экране. Неопределённое сообщение «Что-то пошло не так» не используется.
- Целевой viewport — 1920×1080, проверяемая рабочая граница — 1280×720. Временный minimum window около 1100×700 допустим только как легко удаляемая страховка. Mobile layout и несколько окон не проектируются.
- Цель доступности — WCAG 2.2 AA в применимой к desktop UI части: клавиатура, видимый focus, контраст, отсутствие color-only сигналов, корректные role/name/state, announcements и reduced motion.
- Настройки разделяются на интерфейс, библиотеку, резервные копии и ИИ; обновления показываются отдельной строкой. Телеметрия и автоматические отчёты отсутствуют, диагностический журнал хранится ограниченно и экспортируется явно.
- Русский остаётся единственным языком первой версии. Строки централизуются, но полноценная i18n-система заранее не создаётся.
- Изменения Rust contracts для reader preferences, multiple source fragments, статусов книги, циклов изучения, экспериментов и вех выполняются в канонических Rust-типах. TypeScript bindings регенерируются через ts-rs и не редактируются вручную.
- До первой пользовательской поставки development-форматы состояния могут несовместимо измениться при удалении сеансов. Миграция должна быть атомарной и закрепить новый канонический формат без legacy aliases для тестовых данных.

## Testing Decisions

- Хороший тест проверяет наблюдаемое пользовательское или предметное поведение через самый высокий устойчивый seam. Он не фиксирует внутреннюю структуру компонентов, приватные функции, транспорт Tauri или DOM-детали, уже полностью выраженные скриншотом.
- Главный новый seam — browser E2E через production-like SvelteKit frontend и детерминированный browser test adapter, реализующий тот же предметный command interface, что и Tauri adapter. Это один общий seam для маршрутов, композиции, визуальных состояний и основных пользовательских переходов.
- Playwright использует Page Object Model: page objects инкапсулируют доступные локаторы и пользовательские действия, fixtures создают начальное состояние, а specs владеют assertions и скриншотами. Page objects не строят данные и не содержат assertions.
- Собственный тестовый PDF содержит 8–12 страниц, текстовый слой, оглавление, схему, изображение, повторяемые поисковые фразы и абзац через границу страниц. Он не использует материалы третьих лиц и живёт рядом с E2E fixtures, а не в production static assets.
- Визуальная матрица содержит ровно двенадцать основных baseline: активный рабочий стол, плотная библиотека, обзор книги, чистый reader, reader с заметкой, reader с оглавлением, разбор черновика, деталь идеи, активная практика, завершение книги, настройки резервных копий и первый запуск.
- Основные baseline снимаются в Chromium при 1920×1080. Функциональные сценарии дополнительно проходят при 1280×720; mobile viewport не добавляется. Hover/focus, ошибки, Codex feedback и варианты PDF используют региональные снимки вместо дублирования полных экранов.
- Скриншот является главным assertion для геометрии, темы, видимости и композиции. Тесты не дублируют каждый текст, цвет и control отдельными assertions, если это не добавляет невидимый пользовательский контракт.
- Невидимые browser-инварианты проверяют восстановление позиции/масштаба/layout, фактическое сохранение выделения как черновика, превращение черновика в идею с источником и приостановление предыдущей книги при смене активной.
- Один keyboard-only сценарий проходит reader: открывает сайдбар, ищет текст, сохраняет черновик через Ctrl+Enter, закрывает контекст через Esc и проверяет возврат focus.
- Ключевые страницы проходят автоматическую accessibility-проверку. Она дополняется явными проверками focus order, accessible name/role/state и announcements и не считается заменой ручного аудита.
- Детерминизм обеспечивают локальные шрифты, фиксированные время/date/locale/IDs, явный PDF-ready сигнал, отключённые animations/caret для снимка, закреплённые Chromium/OS image/device scale factor/viewport и сброс данных перед каждым spec. Произвольные timeouts не используются как условие готовности.
- Реальный Codex во всех E2E заменяется контролируемыми success, no-login, crash, cancel и manual-fallback ответами. Browser adapter не попадает в production bundle.
- CI никогда не обновляет baseline. При несовпадении он публикует expected, actual и diff; локальное обновление выполняется только явной командой и сопровождается объяснением пользовательского изменения в PR.
- Pixel tolerance выбирается только после стабильных прогонов и не маскирует систематический недетерминизм. Сначала устраняется источник расхождения, затем обсуждается допустимый порог.
- Vitest и Testing Library остаются для локального поведения сложных shared-контролов, page-local session, форм, keyboard/focus и состояний loading/error/cancel, которые быстрее и точнее проверять без полного E2E. Существующие page-level тесты через injected command fake являются prior art.
- Дублирующие frontend-тесты удаляются только после появления эквивалентного E2E-покрытия. Тесты поведения, которого не видит скриншот, сохраняются на подходящем seam.
- Rust unit/application tests покрывают доменные инварианты удаления календарных сеансов, статусы и циклы изучения, атомарный разбор черновика, multiple source fragments, восстановление знания, эксперименты, завершение изучения и вехи.
- SQLite adapter проверяется интеграционно на временной реальной базе: migration нового канонического состояния, транзакции, foreign keys, FTS5, snapshots, backup и восстановление после прерванной записи.
- IPC contract tests проверяют валидацию, стабильные error codes, сериализацию новых command/snapshot types и воспроизводимую генерацию TypeScript bindings с ожидаемым diff.
- Нативный Tauri smoke suite не повторяет визуальную матрицу. Он проверяет системный импорт PDF, выдачу локального URL/открытие reader и сохранение позиции с восстановлением после перезапуска; конкретный Windows driver выбирается в реализационном этапе.
- PDF vertical slice проверяется на корпусе технических PDF с колонками, листингами, формулами, embedded fonts, ошибочным text order, повреждённым оглавлением, отсутствующим text layer и большим размером. Toolbar должен оставаться отзывчивым, а источники и позиция — корректными.
- Frontend принимается только после format check, lint, Svelte/TypeScript check, Vitest, Playwright и production build. Rust принимается только после rustfmt check, Clippy без warnings и всех Cargo tests; изменения контрактов дополнительно требуют чистой регенерации bindings.

## Out of Scope

- Мобильная компоновка, мобильное приложение, несколько окон и параллельные рабочие контексты.
- Светлая тема и пользовательская перенастройка клавиш.
- Календарь, формальные сеансы, недельный бюджет, учёт времени чтения, пропуски, дедлайны, streak, награды и Google Calendar.
- OCR, рукописные аннотации, выделение изображений и замена PDF существующей книги.
- EPUB, Kindle и другие форматы книг.
- Сетка обложек, папки, пользовательские коллекции, автор, год и расширенный редактор метаданных.
- Граф связей идей и отдельные страницы тем знаний.
- Автоматическое извлечение идей, автоматическое назначение дальнейшей работы и автоматическое изменение знаний ответом ИИ.
- Реальная интеграция Codex в browser E2E и отдельная полная визуальная матрица WebView2.
- Отдельный analytics-раздел, единый процент изучения и витринные метрики.
- Телеметрия, автоматическая отправка диагностических данных и облачная синхронизация личной библиотеки.
- Массовая нормализация frontend-кода в features/entities/widgets до подтверждённого повторного использования.
- Автоматическая реализация всех восьми этапов в рамках публикации этой спецификации; декомпозиция на implementation issues выполняется отдельным шагом.

## Further Notes

- Спецификация синтезирует согласованные UX-принципы, маршруты, wireframes, состояния экранов, reader, дизайн-токены, сценарии и non-goals из `docs/product/ux-redesign.md`.
- Playwright POM, fixtures, двенадцать baseline, невидимые инварианты, accessibility и CI-поведение определены в `docs/testing/playwright-visual-testing.md`.
- Порядок поставки задан восемью этапами из `docs/product/ux-redesign-plan.md`; этапы не являются разрешением выполнять всю работу одним изменением.
- Термины соответствуют `CONTEXT.md`: «режим чтения», «черновая заметка», «очередь разбора», «идея книги», «источник идеи», «незавершённая работа», «веха изучения», «прогресс чтения» и «прогресс изучения» не заменяются близкими, но иными понятиями.
- Спецификация следует ADR-0007 и не моделирует изучение календарными сеансами. Она следует ADR-0008 и использует адресуемые маршруты как восстанавливаемые рабочие контексты.
- Архитектурная часть согласована с действующим технологическим стеком: Svelte 5/SvelteKit, Tauri 2/Rust, PDF.js, SQLite, Tailwind, Bits UI, ts-rs и Playwright.
- Текущий репозиторий ещё не содержит Playwright suite и целевой route map; существующие Vitest/Testing Library page tests и command adapter являются prior art, от которого строится browser seam.
- Главные риски реализации: производительность и доступность непрерывного PDF.js viewer в WebView2; позиционирование text-layer highlights и многостраничных источников; атомарное удаление session/debt contracts; изоляция browser adapter; стабильность скриншотов между локальной машиной и CI; сохранение собственной идентичности Bookshelf после первых Full HD baseline.
