# Технический стек Bookshelf

## Целевая конфигурация

| Область | Выбор | Назначение |
| --- | --- | --- |
| Desktop runtime | Tauri 2, стабильный Rust toolchain | Окно приложения, IPC, упаковка и системные возможности |
| Frontend | Svelte 5, TypeScript в strict mode, Vite, pnpm | Интерфейс и локальное состояние взаимодействия |
| UI | Bits UI, Tailwind CSS 4, Lucide Svelte | Доступные headless-примитивы и собственная система компонентов без hosted-ресурсов |
| Навигация | SvelteKit file-based routes и тонкие route entries | Восстанавливаемые адреса рабочих контекстов при сохранении экранной логики в FSD pages |
| Асинхронное состояние | Page-local Svelte 5 state | Атомарная замена полного снимка после Rust-команд без отдельного кеша |
| Формы | Svelte 5 state и нативные ограничения | Интерактивная валидация ввода до отправки команды без отдельного form framework |
| PDF | `pdfjs-dist` и собственный Svelte viewer | Отображение, оглавление, поиск, выделение и восстановление позиции |
| Backend | Rust, Tokio, Serde, `thiserror` | Доменное поведение, внешние асинхронные операции и типизированные ошибки |
| Рабочее состояние | SQLite с FTS5 через `rusqlite` | Транзакции, миграции и полнотекстовый поиск |
| IPC-типы | Канонические Serde-типы и сгенерированные `ts-rs` bindings | Единое описание snapshot/command contracts без ручного дублирования TypeScript-типов |
| Codex | Bundled `codex` binary как Tauri sidecar | ChatGPT-вход и проверки через `codex app-server` по JSONL/stdin/stdout |
| Переносимый архив | Кандидат: tar + zstd внутри passphrase-encrypted age stream | Потоковая упаковка PDF и состояния с проверяемым шифрованием |
| Системные функции | Официальные Tauri plugins: dialog, notification, updater, shell | Только минимально необходимые платформенные адаптеры |
| Проверки | Cargo test, Vitest, Testing Library for Svelte, Playwright, production builds | Rust, frontend, визуальные E2E, контракты адаптеров и собираемость desktop-приложения |
| Качество | rustfmt, Clippy, `svelte-check`, ESLint, Prettier | Единообразное форматирование и статические проверки |

Версии инструментов фиксируются через `rust-toolchain.toml`, `packageManager` и поддерживаемую версию Node; точные версии зависимостей — в `Cargo.lock` и `pnpm-lock.yaml`. Обновления выполняются отдельно и осознанно, а не попутно с рефакторингом.

`age` пока является кандидатом, а не окончательно принятым криптографическим форматом: Rust crate ещё не достиг версии 1.0. Выбор подтверждается отдельным прототипом совместимости, потокового восстановления и поведения при повреждении архива; собственная криптографическая схема не разрабатывается.

## Размещение поведения

### Rust

Rust является владельцем постоянного состояния и доменных инвариантов. Backend остаётся одним crate с небольшими фасадами и private-by-default реализацией:

- `domain` — чистые типы и правила изучения без Tauri и SQLite;
- `application` — сценарии импорта, разбора черновиков, проверки идей, восстановления, экспериментов и завершения изучения;
- `adapters/sqlite` — транзакции, миграции, FTS5 и резервные снимки;
- `adapters/library` — импорт PDF, внутренние пути и контролируемая выдача файлов viewer;
- `adapters/codex` — жизненный цикл sidecar, вход, JSONL-протокол, отмена и нормализация ошибок;
- `adapters/archive` — создание, проверка и импорт зашифрованного переносимого архива;
- `ipc` — небольшие Tauri-команды и события, вызывающие `application` и отображающие типизированные ошибки в стабильный `{ code, message }`.

Внутри слоёв код группируется по предметной способности (`reading`, `drafts`, `ideas`, `study`, `recall`, `archive`, `codex`), а не в технические свалки `types`, `utils` или `helpers`. `application` зависит от небольшого интерфейса `LibraryRepository`; production-адаптер хранит состояние в SQLite, application-тесты используют in-memory адаптер. Системное время и генерация идентификаторов также внедряются через `Clock` и `IdGenerator`; файловая система и SQLite проверяются на реальных временных ресурсах без дополнительных абстракций.

`domain` и обычные application-сценарии остаются синхронными. Tokio используется для действительно асинхронных внешних процессов, включая Codex и updater; длительные блокирующие операции при необходимости выполняются через `spawn_blocking`.

Svelte не отправляет SQL и не собирает цепочки низкоуровневых команд. Например, `resolve_draft` является одной атомарной командой Rust, а не последовательностью `update_note`, `insert_idea`, `link_source` и `delete_draft` из frontend.

### Svelte

Frontend владеет только представлением и незавершённым состоянием взаимодействия:

- layout, навигация, фокус и раскрытые панели;
- содержимое формы до сохранения;
- состояние выделения текста в текущем PDF;
- отображение progress и потоковых событий Codex;
- optimistic UI только там, где операция безопасно откатывается.

SvelteKit route-файлы остаются тонкими входами и импортируют экранную композицию только через публичный `index.ts` соответствующего FSD page slice. Общий shell и route layouts принадлежат `app`; reader использует отдельный distraction-free layout без основной навигации. Это решение заменяет прежний state-only стек экранов согласно ADR-0008.

Page-local session-модуль владеет `$state.raw<LibraryState>`, типизированной навигацией, общими loading/error-состояниями и последовательным выполнением изменяющих команд. Состояние конкретной формы остаётся в её локальном компоненте. Компоненты получают только нужные данные и предметные callbacks, а не весь снимок и универсальный dispatch; глобальный frontend-store не вводится.

Bits UI используется только внутри собственных компонентов из `shared/ui`: экраны Bookshelf не зависят напрямую от его примитивов. Select, Checkbox, Dialog, Tooltip и другие контролы со сложным поведением строятся на Bits; нативные `input` и `textarea` остаются внутри типизированных wrappers. Lucide-иконки дополняют текст; icon-only действия имеют доступное имя. Tailwind-классы и `data-*` состояния оформляют весь прикладной UI без `<style>`, `@apply` и семантических CSS-классов. `global.css` содержит только tokens, reset и общий reduced-motion baseline.

Frontend следует минимальному FSD: одноразовый код остаётся внутри page slice и разбивается там на связные компоненты и модули; `features` и `entities` появляются только после подтверждённого повторного использования.

```text
src/
  app/
  pages/
    library/
      ui/
      model/
      api/
      lib/
      index.ts
  shared/
    ui/
    api/
    lib/
```

## IPC и безопасность

Tauri command — внешний seam Rust-модуля, а не удобный способ вызвать произвольный Rust-код. Для него действуют правила:

- только предметные команды и контрактные типы;
- все входные данные повторно проверяются в Rust независимо от frontend-валидации;
- стабильные машинные коды ошибок отделены от пользовательского текста;
- большие данные не передаются через JSON IPC без необходимости;
- frontend не получает команды общего назначения `read_file`, `execute`, `query_sql` или `open_path`;
- capabilities перечисляются явно для окна, а CSP запрещает удалённые скрипты и неиспользуемые сетевые источники.

При snapshot-модели отдельные копии одинаковых domain, persistence и IPC DTO не создаются. Один канонический набор Rust snapshot/command types сериализуется Serde, а `ts-rs` генерирует из него TypeScript bindings. CI завершается ошибкой, если повторная генерация отличается от сохранённых bindings; сгенерированные файлы не форматируются и не редактируются вручную.

## PDF

Viewer строится на display layer PDF.js, а не на неизменённом generic viewer. Отдельный модуль чтения скрывает:

- загрузку PDF из внутренней библиотеки;
- преобразование PDF destinations в редактируемое оглавление;
- координаты и текст выделения;
- привязку фрагмента к странице и контексту;
- восстановление страницы, масштаба и позиции прокрутки;
- особенности WebView2, WKWebView и WebKitGTK.

WebView получает доступ только к каталогу внутренней библиотеки через ограниченный Tauri asset protocol scope. PDF никогда не загружается с CDN, а worker, шрифты и character maps PDF.js поставляются вместе с приложением.

Прикладное оформление viewer использует Tailwind. Единственное CSS-исключение — локальный файл необходимых vendor/display-layer правил для динамически создаваемого PDF.js text layer; он не содержит прикладных селекторов Bookshelf.

## SQLite

Frontend не использует `@tauri-apps/plugin-sql`. Rust работает с SQLite через `rusqlite` и применяет встроенные миграции до открытия главного окна. При каждом соединении включаются foreign keys и разумный busy timeout; режим WAL используется после проверки восстановления и резервного копирования на целевых ОС.

В текущей итерации Rust возвращает после изменяющей команды полный атомарный снимок `LibraryState`, а page-local модуль Svelte заменяет его целиком через `$state.raw`. Компоненты получают только необходимые им данные и предметные callbacks; TanStack Query и собственный протокол частичных патчей не вводятся.

Если измерения на большой библиотеке покажут неприемлемый объём JSON, задержку записи или IPC, следующим вариантом является нормализованное хранение предметных записей в SQLite, отдельные read models и адресные запросы с явной инвалидизацией кеша. Это направление запомнено, но не входит в текущую итерацию рефакторинга: оно потребует отдельной миграции БД, архивов, снимков и IPC-контрактов.

До первой пользовательской версии текущая итерация может несовместимо изменить development-форматы `library.sqlite3`, облегчённых JSON-снимков и зашифрованных архивов. Legacy aliases и миграции для тестовых данных не поддерживаются; актуальный формат после рефакторинга закрепляется round-trip тестами. Обязательная обратная совместимость и миграционные тесты начинаются перед первой пользовательской поставкой.

FTS5 индексирует авторские формулировки идей, названия книг и тем, материалы для передачи и нужные поля источника. Таблицы FTS обслуживаются адаптером SQLite и не входят в доменную модель.

## Codex App Server

В каждую платформенную сборку входит проверенная версия `codex` для соответствующего target triple. Rust запускает её как sidecar только для входа или явного действия ИИ и общается через стандартный `stdio` JSONL transport.

Адаптер Codex:

- генерируется и тестируется против схемы bundled-версии App Server;
- использует управляемый Codex вход ChatGPT и не получает токены через Bookshelf;
- задаёт отдельные каталоги состояния и пустую рабочую папку без доступа к библиотеке;
- принимает только уже сформированный пакет проверки;
- преобразует поток протокольных событий в несколько предметных событий UI;
- корректно переживает отсутствие бинарника, отказ входа, несовместимую схему, crash и отмену;
- не включает состояние входа и журналы Codex в экспортируемый архив.

## Упаковка и обновления

Первая поставка остаётся Windows-first и создаёт подписанный NSIS installer. Архитектура и CI сразу не используют Windows-only код вне платформенных адаптеров. Последующие цели — подписанный и notarized DMG для macOS, AppImage или Debian package для Linux.

Tauri updater принимает только подписанные обновления. Обновление приложения всегда обновляет совместимую пару Bookshelf и bundled Codex; независимое автоматическое обновление sidecar не допускается.

## Стратегия проверок

- Чистые правила и application-сценарии проверяются Rust unit tests без Tauri runtime.
- SQLite-адаптер проверяется интеграционными тестами на временной реальной базе, включая миграции, FTS5, backup и восстановление после сбоя.
- Svelte-сценарии проверяются Vitest и Testing Library for Svelte через явно внедрённый fake-адаптер команд; тесты не мокают низкоуровневый Tauri `invoke`.
- Playwright запускает browser E2E через детерминированный test adapter, использует Page Object Model и утверждённые скриншоты при `1920×1080`; небольшой набор невизуальных инвариантов и keyboard-only сценарий дополняют визуальные проверки. Реальная интеграция Codex всегда заменяется mock-ответами; отдельные нативные smoke-тесты проверяют только границу Tauri, импорт PDF и восстановление состояния.
- Корпус PDF включает колонки, листинги, формулы, разные embedded fonts, неправильный text order, повреждённое оглавление и большой файл.
- Быстрые frontend и Rust-проверки выполняются на Linux, Windows также проверяет Rust и production Tauri build; Windows, macOS и Linux проверяются для release candidate.
- Большой синтетический снимок контролирует корректность snapshot-модели и собирает размер/время без нестабильного жёсткого порога миллисекунд в CI.

## Первые технические прототипы

1. PDF vertical slice: импортировать файл, открыть его, выделить текст, сохранить источник и восстановить позицию после перезапуска.
2. Codex vertical slice: запустить bundled sidecar, выполнить ChatGPT-вход, отправить один пакет проверки, показать поток ответа и пережить crash процесса.
3. Persistence vertical slice: провести одно изменение доменного состояния в транзакции, найти его через FTS5, создать snapshot и восстановить его.
4. Packaging spike: собрать подписываемый Windows installer и проверить чистую установку без Rust и Node.js на машине пользователя.
5. Archive spike: создать большой зашифрованный архив, проверить перенос, неверный пароль, обрыв записи, повреждение и восстановление поддерживаемым внешним age-инструментом.
