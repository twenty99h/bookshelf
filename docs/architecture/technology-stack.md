# Технический стек Bookshelf

## Целевая конфигурация

| Область | Выбор | Назначение |
| --- | --- | --- |
| Desktop runtime | Tauri 2, стабильный Rust toolchain | Окно приложения, IPC, упаковка и системные возможности |
| Frontend | Svelte 5, TypeScript в strict mode, Vite, pnpm | Интерфейс и локальное состояние взаимодействия |
| UI | Bits UI, Tailwind CSS 4, Lucide Svelte | Доступные headless-примитивы и собственная система компонентов без hosted-ресурсов |
| Навигация | Типизированный стек экранов на Svelte state | Desktop-навигация без URL-router, пока не нужны deep links |
| Асинхронное состояние | TanStack Query adapter for Svelte | Загрузка, кеширование и инвалидирование результатов Rust-команд |
| Формы | Svelte 5 state и Zod | Интерактивная валидация ввода до отправки команды без отдельного form framework |
| PDF | `pdfjs-dist` и собственный Svelte viewer | Отображение, оглавление, поиск, выделение и восстановление позиции |
| Backend | Rust, Tokio, Serde, thiserror, tracing | Доменное поведение, фоновые операции, типизированные ошибки и журналирование |
| Рабочее состояние | SQLite с FTS5 через SQLx | Транзакции, миграции и полнотекстовый поиск |
| IPC-типы | Serde DTO и сгенерированные `ts-rs` bindings | Единое описание данных на Rust-seam без ручного дублирования TypeScript-типов |
| Codex | Bundled `codex` binary как Tauri sidecar | ChatGPT-вход и проверки через `codex app-server` по JSONL/stdin/stdout |
| Переносимый архив | Кандидат: tar + zstd внутри passphrase-encrypted age stream | Потоковая упаковка PDF и состояния с проверяемым шифрованием |
| Системные функции | Официальные Tauri plugins: dialog, notification, updater, shell | Только минимально необходимые платформенные адаптеры |
| Проверки | Cargo test, Vitest, Testing Library for Svelte, WebdriverIO Tauri service | Rust, frontend и сквозные desktop-сценарии |
| Качество | rustfmt, Clippy, `svelte-check`, ESLint, Prettier | Единообразное форматирование и статические проверки |

Конкретные версии фиксируются в `Cargo.lock` и `pnpm-lock.yaml`, а не в этом документе. Обновления выполняются осознанно и проверяются на корпусе технических PDF.

`age` пока является кандидатом, а не окончательно принятым криптографическим форматом: Rust crate ещё не достиг версии 1.0. Выбор подтверждается отдельным прототипом совместимости, потокового восстановления и поведения при повреждении архива; собственная криптографическая схема не разрабатывается.

## Размещение поведения

### Rust

Rust является владельцем постоянного состояния и доменных инвариантов. Его модули:

- `domain` — чистые типы и правила изучения без Tauri и SQLite;
- `application` — сценарии импорта, разбора черновиков, проверки идей, восстановления, экспериментов и завершения изучения;
- `adapters/sqlite` — транзакции, миграции, FTS5 и резервные снимки;
- `adapters/library` — импорт PDF, внутренние пути и контролируемая выдача файлов viewer;
- `adapters/codex` — жизненный цикл sidecar, вход, JSONL-протокол, отмена и нормализация ошибок;
- `adapters/archive` — создание, проверка и импорт зашифрованного переносимого архива;
- `ipc` — небольшие Tauri-команды и события, переводящие DTO в вызовы `application`.

Svelte не отправляет SQL и не собирает цепочки низкоуровневых команд. Например, `resolve_draft` является одной атомарной командой Rust, а не последовательностью `update_note`, `insert_idea`, `link_source` и `delete_draft` из frontend.

### Svelte

Frontend владеет только представлением и незавершённым состоянием взаимодействия:

- layout, навигация, фокус и раскрытые панели;
- содержимое формы до сохранения;
- состояние выделения текста в текущем PDF;
- отображение progress и потоковых событий Codex;
- optimistic UI только там, где операция безопасно откатывается.

Локальное состояние компонента по умолчанию использует runes Svelte 5 (`$state`, `$derived`, `$effect`). Общие stores появляются только для действительно общего состояния окна или потоков событий; доменные сущности не дублируются в глобальном frontend-store. Навигация начинается с типизированного стека экранов, потому что MVP не требует URL, deep links или browser routing.

Bits UI используется только внутри собственных компонентов из `shared/ui`: экраны Bookshelf не зависят напрямую от его примитивов. Этот модуль задаёт визуальные tokens, размеры, keyboard/focus conventions и стандартные состояния ошибок, загрузки и disabled. Tailwind оформляет примитивы через классы и `data-*` состояния; удалённые стили и шрифты не загружаются.

Структура frontend группируется по пользовательским сценариям, а не по техническим типам файлов:

```text
src/
  app/
  features/
    library/
    reading/
    drafts/
    ideas/
    recall/
    experiments/
    transfer/
  platform/
    commands/
    events/
    generated/
  shared/
    ui/
    lib/
```

## IPC и безопасность

Tauri command — внешний seam Rust-модуля, а не удобный способ вызвать произвольный Rust-код. Для него действуют правила:

- только предметные команды и DTO;
- все входные данные повторно проверяются в Rust независимо от Zod;
- стабильные машинные коды ошибок отделены от пользовательского текста;
- большие данные не передаются через JSON IPC без необходимости;
- frontend не получает команды общего назначения `read_file`, `execute`, `query_sql` или `open_path`;
- capabilities перечисляются явно для окна, а CSP запрещает удалённые скрипты и неиспользуемые сетевые источники.

`ts-rs` генерирует TypeScript-типы из публичных Serde DTO во время теста. CI завершается ошибкой, если сгенерированные bindings отличаются от сохранённых в репозитории.

## PDF

Viewer строится на display layer PDF.js, а не на неизменённом generic viewer. Отдельный модуль чтения скрывает:

- загрузку PDF из внутренней библиотеки;
- преобразование PDF destinations в редактируемое оглавление;
- координаты и текст выделения;
- привязку фрагмента к странице и контексту;
- восстановление страницы, масштаба и позиции прокрутки;
- особенности WebView2, WKWebView и WebKitGTK.

WebView получает доступ только к каталогу внутренней библиотеки через ограниченный Tauri asset protocol scope. PDF никогда не загружается с CDN, а worker, шрифты и character maps PDF.js поставляются вместе с приложением.

## SQLite

Frontend не использует `@tauri-apps/plugin-sql`. Rust работает с SQLite через SQLx и применяет встроенные миграции до открытия главного окна. При каждом соединении включаются foreign keys и разумный busy timeout; режим WAL используется после проверки восстановления и резервного копирования на целевых ОС.

FTS5 индексирует авторские формулировки идей, названия книг и тем, материалы для передачи и нужные поля источника. Таблицы FTS обслуживаются адаптером SQLite и не входят в доменную модель.

## Codex App Server

В каждую платформенную сборку входит проверенная версия `codex` для соответствующего target triple. Rust запускает её как sidecar только для входа или явного действия ИИ и общается через стандартный `stdio` JSONL transport.

Адаптер Codex:

- генерируется и тестируется против схемы bundled-версии App Server;
- использует управляемый Codex вход ChatGPT и не получает токены через Bookshelf;
- задаёт отдельные каталоги состояния и пустую рабочую папку без доступа к библиотеке;
- принимает только уже сформированный пакет проверки;
- преобразует поток протокольных событий в несколько предметных событий UI;
- корректно переживает отсутствие бинарника, отказ входа, несовместимую схему, crash и отмену;
- не включает состояние входа и журналы Codex в экспортируемый архив.

## Упаковка и обновления

Первая поставка остаётся Windows-first и создаёт подписанный NSIS installer. Архитектура и CI сразу не используют Windows-only код вне платформенных адаптеров. Последующие цели — подписанный и notarized DMG для macOS, AppImage или Debian package для Linux.

Tauri updater принимает только подписанные обновления. Обновление приложения всегда обновляет совместимую пару Bookshelf и bundled Codex; независимое автоматическое обновление sidecar не допускается.

## Стратегия проверок

- Чистые правила и application-сценарии проверяются Rust unit tests без Tauri runtime.
- SQLite-адаптер проверяется интеграционными тестами на временной реальной базе, включая миграции, FTS5, backup и восстановление после сбоя.
- Svelte-сценарии проверяются Vitest и Testing Library for Svelte с fake-адаптером команд.
- Сквозные критерии MVP проверяются WebdriverIO через собранное Tauri-приложение.
- Корпус PDF включает колонки, листинги, формулы, разные embedded fonts, неправильный text order, повреждённое оглавление и большой файл.
- Минимальная CI-матрица до кроссплатформенного релиза: Windows для каждого изменения; Windows, macOS и Linux для release candidate.

## Первые технические прототипы

1. PDF vertical slice: импортировать файл, открыть его, выделить текст, сохранить источник и восстановить позицию после перезапуска.
2. Codex vertical slice: запустить bundled sidecar, выполнить ChatGPT-вход, отправить один пакет проверки, показать поток ответа и пережить crash процесса.
3. Persistence vertical slice: провести одно изменение доменного состояния в транзакции, найти его через FTS5, создать snapshot и восстановить его.
4. Packaging spike: собрать подписываемый Windows installer и проверить чистую установку без Rust и Node.js на машине пользователя.
5. Archive spike: создать большой зашифрованный архив, проверить перенос, неверный пароль, обрыв записи, повреждение и восстановление поддерживаемым внешним age-инструментом.
