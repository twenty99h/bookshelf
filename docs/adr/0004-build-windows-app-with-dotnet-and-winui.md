# Создавать Windows-приложение на .NET и WinUI 3

Первую версию Bookshelf создаём как нативное Windows-приложение на C# и .NET 10 LTS с WinUI 3 из стабильного канала Windows App SDK. Этот стек соответствует единственной целевой ОС, даёт прямой доступ к локальным файлам, уведомлениям и управлению sidecar-процессом, а также не заставляет оплачивать заранее не заявленную кроссплатформенность.

Рабочее состояние хранится в SQLite: обычная реляционная модель обслуживается через EF Core, а полнотекстовый поиск — через FTS5 и инкапсулированный SQL. UI использует MVVM Toolkit. PDF отображается локально собственным адаптированным viewer на PDF.js внутри WebView2; отдельный модуль чтения скрывает JavaScript-мост, координаты выделения, оглавление и восстановление позиции от остального приложения.

Codex запускается отдельным локальным процессом через `codex app-server` со стандартным `stdio`-транспортом JSONL. Отдельный адаптер владеет версионной схемой протокола, входом ChatGPT, потоком событий и отказами, поэтому изменение экспериментальной интеграции не затрагивает основной цикл изучения. Bookshelf не читает и не хранит OAuth-токены.

Для установки используем MSIX; приложение и .NET runtime публикуются self-contained, а WebView2 использует Evergreen Runtime. Версии Windows App SDK, WebView2, PDF.js и пакетов фиксируются при сборке и обновляются независимо от этого решения.

## Рассмотренные альтернативы

- WPF на .NET зрелее, но для нового Windows-only приложения выбран актуальный нативный UI-стек Microsoft; к WPF стоит вернуться только при подтверждённом блокере WinUI 3.
- Tauri с web UI упростил бы интеграцию PDF.js и оставил путь к другим ОС, но добавил бы Rust/TypeScript ко всему приложению и межпроцессную границу там, где кроссплатформенность не входит в MVP.
- Electron дал бы единый web-стек, но ценой отдельного Chromium runtime, большего дистрибутива и более широкой поверхности обновлений для локального Windows-приложения.

## Последствия

До реализации вертикального среза нужны два ограниченных прототипа: выделение текста и восстановление позиции в PDF.js/WebView2, а также один полный запрос проверки через `codex app-server` с изолированной рабочей папкой. Криптографический формат переносимого архива остаётся отдельным решением после проверки библиотек и сценария восстановления; сам выбор .NET его не предопределяет.
